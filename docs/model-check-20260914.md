## 验证方法与范围

对个人配置中 7 个启用的不同模型，分别建立独立临时目录，通过 spawn_agent
显式指定型号及推理档位。每个 worker 必须读取一个存在错误的 Python 函数，
修改 invoice.py，并运行 python3 -B -m unittest -v。测试文件不得修改。

任务是用 Decimal 累加商品金额，正确处理数量、空输入、小数精度、零数量，
并拒绝负数量。每个模型对应 5 个测试。主 agent 独立阅读所有改动、复跑测试，
核对各目录的测试文件 SHA-256 一致。子 agent 完成后均已关闭。

## 结果边界与后续方案

本轮证明这些显式委托请求完成了有工具的基本工作，不验证供应商内部的实际
模型身份、账单、百万上下文、复杂工程效果或长时间稳定性。此前两个 GPT 的
认证问题不能推广为所有 GPT 都不可用，且本轮未排查其根因。

减少主 agent 依赖的下一步，是把任务状态、候选选择、尝试预算及故障记录放到
独立程序，主 agent 只提交任务及消费结果。MCP 可以暴露这套程序的工具入口，
但单纯把脚本包装为 MCP 并不能保证主 agent 一定调用它。若要强制工作流，需
由外部入口或宿主统一接收任务、发起执行和记录状态。

独立程序也不能直接调用只存在于当前模型回合里的原生 spawn_agent 工具。
需要经过支持的宿主 API，或使用独立的 Codex CLI 执行进程等适配层。当前
codex exec 和 codex exec resume 的帮助确认有 --model、--json 参数，可作为
外部调度原型的基础；恢复已有 CLI 会话仍需验证，不能承诺透明恢复桌面线程。

主模型失效时，可以由代理在适当请求边界重试，也可以由外部守护程序选择
另一个主模型、依据已保存会话/任务状态续做。二者都要避免重放已经执行的
副作用。代理不能无条件重试已经输出内容的流；程序恢复前需确认旧执行者
终止，并核查部分修改。全部候选共享的额度耗尽仍不能通过换型号解决。

Linux 结论限于本机已验证的安装、配置保留、解析器及上述模型任务；不代表
所有 Linux 发行版、依赖版本、网络条件或故障场景都没有问题。macOS/WSL
尚未实机验证。
