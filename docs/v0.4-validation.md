## 真实模型委托观察

| 显式委托参数 | 实际观察 | 可以证明的范围 |
|---|---|---|
| glm-5.3 / low | 子 agent 完成安装器文件修改与本地测试；主 agent 读取、修正并验证产物 | 本轮该委托请求完成了带工具的编码工作 |
| gpt-5.4 / medium | 返回该型号不支持当前 ChatGPT 账户认证的错误 | 本轮此委托路径失败；不能认定是额度不足 |
| gpt-5.2 / medium | 返回同类认证错误 | 本轮此备选路径也失败 |

这纠正了“工具说明未列出 GLM，所以 GLM 不能委托”的潜在误判：本轮 GLM
实际完成任务，说明那份简短列表不是完整的拒绝名单。反过来，目录或工具
说明列出了某型号，也不能证明当前认证能够使用它。

此记录依据委托参数、工具状态和产物，不以模型自述证明实际型号。没有获得
上游账单或实际返回模型的独立核验；不宣称所有别名和推理档位均测试通过。

本机仅停用 discussion-main（gpt-5.4）及 discussion-backup（gpt-5.2）这两个
已确认失败的 profile，普通讨论沿角色池选择 glm-5.3。其他 GPT/GLM 候选
未在本轮逐个实测；分享包保留默认候选，安装者需自行核实认证和可用性。

本机当前会话证据快照保存在 ~/.config/task-router/runtime-observation-20260914.json，
通过显式 --runtime 加载，有一小时有效期，不随插件传播，也不等同于持久化
健康状态。认证修复后需要重新核实并启用相应 profile。
